# Shared Find for native tmux panes

**Goal:** Give explicit local Unix tmux panes the same bounded Find workflow as normal terminal panes, without adding persistent chrome.

**Architecture:** Extract the existing compact bar and its pane binding into `FindBar : Border`. Each `TerminalPane` retains its existing `PaneFindController`; the bar subscribes to only the current pane. MainWindow delegates to the component. TmuxWindow shows it on Find and rebinds it on pane/tab changes; closing, removal and detach cancel pending work. No VT, tmux protocol or process ownership changes.

**Tech stack:** Existing .NET 10.0.402 / Avalonia 12.1.4 / pinned terminal control. No dependency changes.

The alternatives were copying MainWindow's UI/events into TmuxWindow or treating a tmux view as a MainWindow. Copying would create two implementations of focus/cancellation/error handling; inheritance would mix different session ownership. The shared bar keeps the existing controller and thin native windows.

Pinned reference: iTerm2 069b6e0dd8f3f0d82fc08ea5d294d28f7c5b986e, `sources/SearchingFiltering/iTermFindDriver.m` (mode/query/view navigation) and the existing tmux migration source map. This work reuses Aster's verified matcher and UI; it does not implement upstream smart case, filtering or automatic -CC interception.
